# Dependency risk review

This is dependency triage, not an independent security audit or a claim of exploitability. After reverting the unsuccessful UUID remediation experiment, the current lockfile audit reports **27 affected packages: 22 moderate, 5 high, 0 critical**. The pre-experiment baseline was also 27; the rejected candidate lock reported 24 but still contained vulnerable UUID copies. Many entries propagate the same underlying advisory through parent packages; the three distinct advisory IDs and their dispositions are below. The existing `ws@^8.0.0` override is the only accepted override. Current verification results are recorded in `CURRENT_STATE.md`.

| Advisory | Installed path | Exposure and disposition |
| --- | --- | --- |
| [braces stack-exhaustion DoS](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) | `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces@3.0.3` | Development lint tooling. npm's latest release is still 3.0.3, within the advisory's `<=3.0.3` range. Do not run tooling over untrusted glob patterns. No patched release was available during this review. |
| [decode-uri-component decoding DoS](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr) | `wagmi → @wagmi/connectors → @walletconnect/ethereum-provider → @walletconnect/utils → query-string@7.1.3 → decode-uri-component@0.2.2` | WalletConnect dependency. The patched 0.5.0 release is ESM-only, whereas this `query-string` imports it with CommonJS `require`. A blind override across that module boundary is not a verified fix; upgrade the parent integration and test its wallet flows together. |
| [uuid buffer bounds check](https://github.com/advisories/GHSA-w5hq-g745-h8pq) | MetaMask SDK/utilities (also reached through Gemini and legacy Coinbase connector dependencies), current lock contains `uuid@8.3.2` / `9.0.1` | Two candidate resolutions to 11.1.1 were rejected: parent-scoped overrides plus `npm update uuid --package-lock-only`, then version-scoped `uuid@^8.0.0` / `uuid@^9.0.0` overrides. Both left `uuid@9.0.1` copies under `@metamask/utils`; the focused version guard correctly failed, and `npm ls uuid --all` reported `ELSPROBLEMS`. The test did not observe a v4/validate API compatibility failure; it stopped at the remaining version mismatch. The UUID overrides, test-script addition, test file and lock edits were reverted. The advisory remains unresolved. |

`Providers` registers only the injected-wallet connector unless `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID` is supplied, in which case WalletConnect is also offered. It does not register MetaMask SDK, Gemini or Coinbase-specific connectors. Installed dependency presence alone does not establish that the vulnerable function executes in this app, but connector selection is **not** proof those dependencies are absent from bundles or safe. This review did not establish end-to-end exploitability or certify runtime reachability.

## Release boundary

- Keep mainnet paused. Keep WalletConnect unconfigured until its dependency path has a supported fix and its actual UI flow is tested; installed/injected wallets remain available.
- Do not downgrade Next/ESLint or migrate wagmi major versions solely to satisfy npm's suggested remediation. Its suggestions currently include `eslint-config-next@14.2.35` and `wagmi@3.7.7`, not compatible in-place patches for this stack.
- Review upstream releases, regenerate the lockfile, and run tests, ABI checks, lint, typecheck and production build before accepting dependency changes. Wallet-stack changes also need real connector testing.
- Re-run `npm audit --json` when dependencies change. Counts are lockfile/advisory snapshots, not a permanent safety rating. The braces and decode-uri-component findings remain open.

The tested candidate, [uuid 11.1.1](https://github.com/uuidjs/uuid/blob/v11.1.1/CHANGELOG.md), is a security backport that retains CommonJS and ESM exports. Its relevant `v4`/`validate` surface was not observed to be incompatible; resolution coverage failed because some consumers still received 9.0.1. No UUID override remains in the current manifest. Wallet and framework versions stay pinned as before. Browser verification uses the registered injected-wallet path, not MetaMask SDK remote/mobile pairing; the latter remains untested and unregistered.

Evidence for this review: current `npm audit --json`, candidate `npm ls uuid --all` output (`ELSPROBLEMS`), npm release metadata, `query-string/index.js`, and the connector list in `web/src/components/providers.tsx`.
